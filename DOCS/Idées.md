# Idées pour Liora

Revue du 25 septembre 2026. Les trois premières propositions P0 (rappels/récurrences, Web Push et mutations) et la mise à jour PWA ont été implémentées en 0.4.7 ; leur qualification de déploiement reste à effectuer. Les autres propositions prolongent la charte ; elles ne sont ni activées ni promises. L’[état du projet](ETAT_DU_PROJET.md) et la [roadmap](../ROADMAP.md) priment sur de nouvelles fonctionnalités.

Classes : **CORE** pour la fiabilité du socle, **FEATURE** pour une extension directe, **FUTURE** pour un produit ultérieur, **EXPERIMENTAL** pour une piste à éprouver. P0 précède une livraison fiable, P1 améliore l’usage quotidien, P2 reste à arbitrer.

## Ordre conseillé

1. Finir la qualification heartbeat sur Argus.
2. Qualifier les rappels et Web Push sur le déploiement réel après la validation locale 0.4.7.
3. Consolider restauration, PWA, permissions et accessibilité.
4. Choisir une extension quotidienne mesurable (vue Aujourd’hui ou incidents), puis seulement arbitrer 0.5 et les pistes expérimentales.

La synchronisation PC ↔ serveur reste un module LUMA distinct. Vocal/vidéo, marketplace bots et commandes d’administration de serveurs restent hors du cœur actuel. Aucune de ces idées ne justifie de déverrouiller une fonctionnalité incomplète.
